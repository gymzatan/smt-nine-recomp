# DPC stack and exception registrations

The existing DPC dispatcher reuses the standing 0x3000-byte guest stack recorded in its PCR. The main PCR receives its process-lifetime stack during memory initialization. Spawned PCRs reserve 0x60 bytes before TLS and include their standing DPC stack in the same original TIB/TLS/thread allocation; the existing object release frees that entire allocation. No stack is allocated, cleared or freed for an individual callback. It publishes the active dispatcher stack pointer and standing stack top in the original PCR fields at FS+0x58 and FS+0x5c, isolates FS:[0], and restores the interrupted ESP, EBP, SEH frame, exception chain and IRQL after the callback. KeIsExecutingDpc reads that same active flag. Timer and deferred queue identities and ordering remain unchanged.

Original kernel 4627 at 0x8001B08F publishes its dispatcher entry ESP in PCR+0x58. The existing runtime retains the two dispatcher stack words above its callback arguments and publishes that pointer. Original kernel 4627 at 0x80018D30 switches ESP to PCR.DpcStack and isolates the exception chain before its DPC dispatcher. Original exception dispatch at 0x80023BFF and unwind at 0x80023D70 accept aligned registrations in the active stack's final 0x3000 bytes when IRQL is at least DISPATCH_LEVEL. The runtime's dispatch and unwind consume one shared validator implementing those bounds. The active PCR fields are guest RAM retained by the original memory checkpoint.

Native continuation 0x194 retains this callback activation and its standing stack identity. The original continuation fixture exercises cold and same-process recovery after a callback explicitly lowers IRQL before waiting; original caller and callback operations execute once. The timer device worker still owns its existing device checkpoint boundary while running callbacks. This delivery does not make that worker independently resumable during a callback or authorize blocking at DISPATCH_LEVEL.

The physical-memory checkpoint identity is XBPCRS. The former compact-PCR identity XBPHYS is rejected before mutation, because its TLS placement overlaps the now-observable PCR fields. Five original thread/context checks verify PCR/TLS isolation and the existing spawned/inline register consumers. Fourteen native checks cover real callback layout, CPU ownership, stack isolation/restoration, active and IRQL boundary rejection, exception dispatch and RtlUnwind from the actual DPC stack. Two existing continuation modes cover wait recovery. Parent integration owns the full application build.
