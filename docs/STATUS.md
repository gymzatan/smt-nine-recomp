# Current scope and validation

The accepted Windows native port is approved for an early playable release. Polygon Z offset, stencil operations and integer/floating depth consumers use the existing renderer paths. Color logic operations reach software, D3D11/D3D12, Vulkan and the pinned OpenGL dependency, whose affected output checks pass. Guest device/event/timer/interrupt/DPC consumers retain the original object tables and scheduler. Nonconstant W slope, finer raster coverage, other documented compatibility limits and complete playthrough coverage remain unfinished. The [runtime compatibility status](COMPATIBILITY.md) records the connected consumers and remaining boundaries; release approval does not establish whole-game equivalence.

The reported demon-status/confirmation menu and sustained fusion slowdown remain performance issues awaiting in-game acceptance. The original font-table partition branch is corrected and isolated checks cover ordering and lookup behavior. The earlier 19-of-200 font-lookup PC observations identify local instruction residency, not a calibrated time share or evidence that the current menu slowdown is resolved. Static checks and isolated cost measurements do not establish an end-to-end speed improvement.

Native line shaders reject unused width-copy instances before local clipping, visibility and coordinate conversion. The original width, render scale and 32-copy grouping still determine output. This removes redundant work on the shared line path; it does not establish an end-to-end menu or fusion frame-rate improvement.

The supplied animation crash is repaired by connecting guest C++ exception dispatch to the original registered handlers, destructor actions and catch bodies. The function catalog includes the original C++ registration thunks, and the selected catch continuation rebuilds the retained native callers through the existing continuation engine. This preserves the original resource-not-ready exception path and prevents execution from falling through into construction with an empty resource. The original catch/cleanup mechanism has supplied-scene replay coverage. Native registration validation consumes the actual main or owned thread stack independently of the TLS pointer; this bound correction has component coverage, with no new full-animation replay. Existing performance changes remain in place; no full-game performance improvement is claimed from this scene test. The current image has 1,902 identified C++ registration thunks, each included once in the function and dispatch catalogs. Other threads, nested or different exception paths and a complete playthrough remain outside this scene verification.

FSIN, FCOS, FPTAN and FSINCOS produce their own C2 range indication. Successful existing libm evaluation clears C2; finite operands with absolute value at least 2^63 set C2 and retain the original physical operand, raw alias, tags and stack depth. The existing full-libm FPREM/FPREM1 reduction clears C2 when complete, so the CRT sine, cosine and tangent FNSTSW/SAHF/JP loops observe completion. Their three remainder consumers read only C2. Partial-reduction timing, quotient condition bits and general nonfinite exception fidelity are not certified by this contract. The original arithmetic, status reader, continuation engine and checkpoint fields remain authoritative.

The initial source release uses the existing accepted native port. It is an early playable release with defined remaining coverage; it does not claim the complete game has been finished or that every scene maintains normal-speed 60 FPS.

Existing runtime verification includes startup, Japanese/Chinese/English selection, ordinary saves and loads, movies, field navigation and shops, story battles, RTS tutorials, chapter two entry, display/aspect options, pause/screenshots and exact-executable instant-state recovery. The reported post-hacking second story battle proceeds through its following street dialogue and Central Administration Bureau scene with the delivered executable. The ordinary Status demon view has been verified with Sphinx, Cait Sith and Tsukuyomi. Its body projection and animated-effect viewport use the same widescreen mapping as the surrounding panel.

Current scene handling keeps the projected speaker endpoint at its world-screen position while the speech window and connector text end share the existing UI mapping. The per-frame popup update retains measured Chinese line width. CLOVER preserves the original appearance scale on both shader axes before applying widescreen X mapping. On the movie EOF frame, teardown returns through the existing epilogue so the following scene can render before dialogue contexts advance. Targeted helper and compiled-function checks cover these changes; the exact reported Legion movie boundary and all CLOVER appearance variants have not been recaptured in game.

Window entry effects reuse the visible UI rectangle for both the original transition mesh and its captured-texture sampling. The two-body Manual fusion entry was replayed through all eleven transition draws at 16:9; its source and screen left edges agree with the settled list. This shared window path also serves shop lists. A separate buy/sell replay remains outside the current verification.

Config supports independently saved keyboard and XInput bindings for 24 game actions, input capture, unbound inputs and restoring defaults. It reuses the existing window-key and controller polling paths; analog pressure, foreground gating and the keyboard/controller merge remain in place.

The original callback catalog includes long exception-handled callbacks, forwarding entries and conditionally selected pointers, with their original out-of-line branch ranges. The supplied Shibuya story battle state runs through a 30-minute supervised replay without the reported unresolved-call exit; displayed verification includes later battle turns and skill effects. Full-game computed-target and battle coverage remains incomplete.

Replaying the supplied corridor state reaches the following room, dialogue and battle without the reported black screen. Battle item and reward icons use the same horizontal UI mapping as their surrounding panels and text, preserving their original placement at 4:3.

The random-encounter gauge frame uses the same horizontal mapping as its fill and nearby command panels. Native Vulkan readback buffers prefer compatible host-cached memory. Battle effect initialization checks completed callback outputs instead of uninitialized object fields; focused regressions and a ten-minute diagnostic replay cover the reproduced failure. Heavy battle scenes and wider long-session coverage still need performance work.

The existing APU producer runs at above-normal thread priority so that competing foreground CPU work does not starve its audio deadline. Its PCM format, queue capacity, callbacks, game pacing and checkpoint state remain unchanged. Foreground/background replay and the original audio-state restoration checks cover this scheduling change; system-wide audio interruptions and affected-player hardware remain unverified.

The shared native-renderer texture cache indexes the original full texture identity and tracks only content-valid entries for write invalidation. Invalid historical entries do not participate in invalidation scans. Ordered GPU output queries retain reusable array capacity instead of reallocating on each append. Resource decoding, memory protection, output ordering and checkpoint behavior keep their existing paths; cache retention is unchanged. These changes have static review and compilation coverage; their whole-game performance effect has not been measured.

Native draw preparation uploads original cached vertex rows and the separate index array directly into the existing contiguous D3D ring buffer with one map. Reused GPU ranges need neither staging copy nor index packing. Texture binding receives the current draw target instead of resolving its identity again, retains any upload required by intervening output completion, and unchanged D3D render-state writes preserve the existing combiner dirty state without requesting another parse. The same resource identities, upload generations, offsets and draw order remain authoritative. These paths have static review and build coverage only.

Repeated GPU-progress polls reuse an existing posted worker request instead of repeatedly updating its atomic word. Actual command submission retains its publication barrier, and a running worker without another request still receives one. Pending-output, ordered-queue and checkpoint checks cover this boundary; menu and fusion FPS improvement remains unverified.

Known coverage limits:

- Horizontal character gaps and incorrect occlusion have been reported on some player configurations. Local four-backend street samples and an AMD-integrated D3D11 sample did not reproduce them; the exact female-player and restaurant scenes, affected builds and drivers remain unverified. A graphics-memory cause has not been established, and 512 MiB support is not certified. See the README for hardware requirements and memory-report fields.
- Full playthrough, later chapters, all battles, complete audio coverage and long-session stability remain incomplete.
- Performance in heavy scenes still needs work. Selecting 60 Hz is not a promise that every scene maintains it.
- Fusion callbacks, encoding and the original two-demon selector have been exercised. The supplied sword-fusion route reaches confirmation, animation and result with matched model/platform projection at 4:3 and 16:9. Ordinary two-body and three-body routes also reach their results at 16:9, with material and result roots aligned to the backdrop discs while model proportions stay normal. Every possible combination has not been tested.
- CLOVER viewport/projection corrections are integrated; complete appearance-route visual coverage remains pending.
- Later hardware/render states can still expose explicit unsupported boundaries. The runtime does not silently turn them into successful operations.
- Newly edited Chinese text has structural/reference verification, but every scene has not been replayed in game.

The [source-package validation](VALIDATION.md) records the fresh disc-to-native build, startup, ordinary loading, external-language import/update and same-executable checkpoint scope separately from this existing gameplay coverage. No old checkpoint is treated as proof that a new executable can restore it.
