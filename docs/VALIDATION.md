## Graphics processing modes

Config defaults to multithreaded graphics processing, including installations whose existing profile has no `MultithreadedGraphics` key. The explicit single-threaded selection uses the same FIFO parser, renderer and completion queries on the game execution thread. It does not constrain process affinity. Both modes retain the original guest-CPU ordering; multithreaded mode adds one ordered graphics consumer, release/acquire PUT/GET visibility and coalesced wakeups. Register access and CPU-visible rendering outputs share the device lock. CPU-owned PFB registers do not wait for rendering. Checkpoint freeze includes the graphics worker and reconstructs notification state from the restored device queue.

A same-executable shoe-store comparison at Japanese, Vulkan, 1×, 4:3 and 60 Hz measured two 15-second windows per mode. Single-threaded results were 59.80 and 60.47 FPS, with main-thread CPU times of 13.80 and 14.03 seconds. Multithreaded results were 60.46 and 60.40 FPS, with main-thread CPU times of 6.88 and 6.59 seconds and graphics-worker times of 8.00 and 7.53 seconds. Main-thread CPU time decreased about 52%; combined game/graphics CPU work increased slightly. This demonstrates work distribution and additional main-thread headroom, not a 52% frame-rate improvement, a universal 29% gain or stable 60 FPS across the game.
