# Source release validation

Fatal-report checks run the production writer in child processes for explicit termination, an unhandled native exception, C runtime abort and direct fatal notification. They verify the current log excerpts and context, a bounded report for long logs, unchanged normal/handled-exception behavior, an unwritable destination and an unreadable guest diagnostic callback. The original guest-context reader is separately exercised with valid, partially readable and unmapped stack inputs; diagnostic reads retain only accessible bytes. Native stack filtering uses the actual executable extent under ASLR. These are diagnostics and source-safety checks, not a reproduction or confirmed fix of the reported player-only outdoor-background loss or underground-street crash.

CPU preparation checks exercise actual production batch and draw helpers across D3D11, scaled D3D11, native Vulkan, D3D12 and OpenGL. Real call counters and old-source negative controls distinguish redundant preparation from the final pixel/geometry consumers. Original polygon pixels, query results, constant-buffer slot contents, resource lifetimes and byte comparisons remain checked. Kernel fixtures show that zero log budget performs no ordinal-summary clock/counter work while preserving dispatch, watch results and enabled diagnostic output; disabled I/O timing likewise performs no start clock.

The selected DSP register allocator passes the original 31 library, 1009 instruction and 16 C API checks. An isolated replay uses the original machine-section SHA1 reader and original physical-memory/APU loaders on the same battle snapshot, then the original VP, GP, EP, DMA and AC97 calls. All three output streams are byte-identical. In this short replay the first eight DSP frames take about 66.53 ms rather than 40.17 ms; the following 504 take about 45.84 ms rather than 55.03 ms. These are local audio-processing measurements with a cold-compilation tradeoff, not whole-game FPS or weaker-computer performance certification. Source/consumer coverage and preserved outputs do not prove that every guest instruction is mathematically minimal.

## Graphics processing modes
