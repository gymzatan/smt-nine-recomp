# Source release validation

The Chinese-enabled source package was built in a separate Windows directory from the supported Japanese retail ISO, repository inputs and the dependencies listed in BUILDING.md. No developer game executable, extracted Media, generated game C, prepared XBE, font container or compiled DSP library was used as a build input. A fresh Python environment was installed from the requirements file. Windows SimSun/SimHei supplied the font inputs.

Optional-language checks cover the build driver's dependency selection and resume settings, plus the compiled production Config/language APIs with Chinese enabled and disabled. A separate Japanese-only host and imported English package were built without Chinese Media, high-resolution font atlases or a Chinese runtime image; both reached the title menu from an absent shared save root. Startup created ordinary save directories and no partition images. This validation reused verified extracted assets, DSP and generated baseline files; the shared code-generation image was rebuilt from retail and matched the accepted input byte for byte. It was not another complete ISO-to-resources rebuild. Chinese game selection is unavailable in this build, while imported English and all three interface languages remain supported.

Retail extraction was exercised on a 2,188,050,432-byte XISO and a 7,825,162,240-byte full-disc dump. The existing reader found the game partitions at offsets 0 and 0x18300000; both produced the same 3,515 files, each matching the retail manifest used by the completed native build. The original XBE SHA-256 was `6c249401369ed41c2a319762f0b56b80aefde3efe766ac0d8731889a4150deac`. This verifies the alternative input layouts through extraction; the unchanged downstream compilation was not repeated for each container.

An original extracted folder was also copied through the production preparation path: all 3,515 destination files match the retail manifest, and the source hashes and modification times are preserved. Folder checks cover changed/missing/extra files being rejected before copying, source/destination overlap and input records. Build-driver checks cover both initial language selections from either an ISO or a folder, same-input resume and program-only updates.

Extraction regression checks cover both ISO layouts with different container padding, changed file contents, missing/extra files and installed-resource verification. Build-driver checks also cover program updates from a different input-container identity and reject switching inputs during resume. The normal source selection passes 44 checks; the existing XDVDFS reader's six additional checks also pass.

The existing writers rebuilt the Chinese scripts, fixed fields, fonts, title, staff list and five subtitled movies. The rebuilt native image's sections match the accepted development image byte for byte; only the original certificate title differs. All 22,325 generated function bodies passed the recorded generation hashes. The title bundle matches the accepted bundle. The subtitle writer retained all 24 original audio tracks across 7,631 movie frames and checked the original audio and packet timing. These are rebuild checks, not claims that every translated scene has been played.

The native host, Config and DSP library compiled from source. The native configuration is Release with machine checkpoints enabled. Runtime checks covered:

- Japanese startup/title and an ordinary LOAD01 read.
- Chinese startup, ordinary LOAD10, chapter-two dialogue, a city transition and Status → Demons with Sphinx correctly inside the model panel at 16:9.
- Chinese F9 pause/resume, a new instant save and strict same-executable cold restore back into the Sphinx Status view. F8 captured the restored displayed surface. Captures were taken at different running frames and were not an exact-frame pixel comparison.
- First English import through Config and the ISO picker, a rebuilt package update, language selection, English title/load menu, ordinary LOAD01 into the street, F8 and F9 pause. The English patch and ISO remain external user inputs.
- An intentionally invalid update failed while preserving the existing ready English registration and releasing the import lock.
- The native executables were copied to D:, renamed into a directory containing Chinese characters and spaces, and launched directly with a different working directory. Config displayed its Chinese interface and saved settings in that moved folder. The game reached the title menu and F8 wrote into that folder. Both executables use the Windows GUI subsystem, so direct launch requires no command script or console window. The delivered play folder excludes the test-created saves and caches.
- The Option screen's RGB message-background fills align with their slider frames at 16:9, verified on the displayed surface. Their original direct color-quad entry uses the existing UI coordinate mapping. Targeted checks cover empty, fractional and populated fills, preserve all non-X vertex bytes and leave 4:3 unchanged.

The menu graphics audit checks the original shared scrollbar, icon and connector paths. See [MENU_UI.md](MENU_UI.md) for producer identities, displayed coverage and progression-dependent limits.

New-game displayed recordings also cover the mother/sister and red-haired communications portrait transitions, including entry and exit. The original 22-vertex strip renderer shares the existing UI mapping throughout its animation. The actual helper checks preserve 4:3 coordinates and all non-X vertex bytes.

Closing the framebuffer window ends the game process. A hidden test reproduced the previous lifecycle race: clearing the running flag on close allowed the next guest clear to start another window thread before the old thread finished. The close handler now uses the runtime's existing process-exit behavior. Closing the rebuilt game, including while F9-paused, was verified to terminate the process without creating another framebuffer window.

The ordinary save fixture was copied into the private verification directory only after the disc-to-native build completed. No old instant state was used to establish fresh startup or ordinary-load success. Test processes were closed after verification.

Source-only CI runs the content audit and the targeted build/integration checks without requiring a game disc. It does not run the game or substitute for the clean local build. See [STATUS.md](STATUS.md) for remaining gameplay and performance coverage.

PC storage checks execute the production path and file APIs in a fresh temporary directory, reject partition-image creation, and verify ordinary-save writes followed by close/reopen/read, volume queries, and imported-language cache isolation. The final game reaches the title with a fresh runtime save directory and creates no partition images.

Graphics startup tests execute the production selection loop with failed DLL loads and failed driver calls, including general failure and invalid-argument results, and check release of partial objects, exhaustion and exclusive manual selection. Actual D3D11, Vulkan and OpenGL device/resource checks pass; disabling all Vulkan ICDs reaches OpenGL through Auto. With both Vulkan unavailable and the private test copy of the OpenGL D3D11 DLL absent, Auto reaches system D3D11 and completes actual drawing, colour/depth readback and checkpoint checks. Keeping each runtime module loaded for the process avoids the reproduced native-driver failure and later draw crash caused by unloading WineD3D during selection. A direct GUI launch with unavailable manual Vulkan produces a readable bilingual error dialog and startup log. This does not establish compatibility with every driver or recover a driver that crashes or hangs inside its own call.

Japanese 1x, 4:3 performance checks use the original live counters. A five-second OpenGL load-device screen measured 1.80 FPS at about 41 draws/frame with the default timer and 30.60 FPS at 40 draws/frame with the 1 ms request; neither sample uploaded textures. The same host wait API requested for 0.1 ms measured a median 15.12 ms by default and 0.99 ms with the request. Separate five-second street and NPC dialogue samples reached about 30 FPS on OpenGL and D3D11. These local results do not establish performance on every GPU or reproduce the exact user screenshot. Startup tests also check timer acquisition failure, exit-registration failure and balanced cleanup.

Font checks execute the production loader and lookup, verify read-only mapped storage and unchanged pixels, and reject truncated, trailing, mismatched and malformed containers. The 78 lookup outputs from the existing two-, three- and four-times font bundles have identical pixel hashes to the previous loader. In separate local processes, font initialization added about 108/238/420 MiB of private memory before the mapping change and less than 1 MiB afterwards; source mapping pages remain file-backed and demand-paged. These measurements cover font initialization, not whole-game FPS or GPU memory consumption.

The Config window-size presets, custom dimensions and Fixed Aspect Ratio checkbox were exercised through the real dialog in Chinese, Japanese and English, including save and reload. Resize checks execute the production window handler for all eight edges/corners at 4:3, 16:9 and a custom size, with a different game aspect to verify independence. They also check the system tracking limit, free resizing and the fullscreen exemption. Config and game checks use isolated copies and do not alter user settings or saves.

The Chinese large-dialogue inputs use the reviewed Chinese speaker width for continuation indentation. The completed male/female script inputs include 126 adjusted records and 908 adjusted lines. Both RL resources were rebuilt from the retail disc through the existing writer. The native verifier checked all 396 retail-bound records against their actual displayed-text and execution timelines, including scene identities, choice operands and other text channels. A hidden native new-game run captured the red-haired communications introduction and talk branch; continuation lines align with the first line's body after the speaker name. The public recipe preserves retail records, so its resource bytes differ from the prepared Xbox translation baseline.

Fixed-function eye-linear/object-linear texture generation and texture matrices consume the original CSV1 state and XF constants. Production-shader GPU output checks cover all texture stages/components, disabled coordinates and matrix enable/disable. The full original-method consumer checks pass on D3D11 and Vulkan at render scale three, including XYZRHW draws that require texture generation. Unsupported sphere/normal/reflection generation remains an explicit boundary.

The reported second story battle after the hacking tutorial was replayed from the user's preserved Slot 5 with the delivered executable, in Chinese at Vulkan render scale three, 1920x1080, 16:9 and 60 Hz. Entering the adjacent passage triggered the encounter; displayed captures cover battle actions, the following street dialogue and the Central Administration Bureau scene. The process continued through this route without the original rendering stop or a crash, then closed normally. This establishes coverage for this encounter, not a full playthrough or long-session stability.

That diagnostic replay used a separate, explicitly migrated checkpoint copy after reviewing compatibility: the game image, all 97 generated continuation files and the serialized state layouts were unchanged. Only the copy's executable digest was updated; all ten payload digests and their bytes were preserved and checked. The original Slot 5 and matching executable were retained unchanged. The production loader was not modified and still requires an exact executable match; this one-off verification does not establish general compatibility between instant states from different builds.

Small-dialogue connector checks use the captured original eight-vertex payload and submit each of the two strips separately. Rebuilt Chinese game captures at Vulkan, render scale three and 60 Hz show the underline aligned with the speech text/background in the Cerberus sequence and the reported post-hacking encounter. Controller checks execute the production Windows mapping with individual shoulders, partial trigger pressures, combined buttons and release.

HQ displayed-surface checks at 16:9 cover changing speakers, dialogue choices and different Chinese line lengths. The connector endpoint follows the speaking character and the underline follows the measured window. Actual helper checks cover projected points on both sides of the screen, interpolation progress and unrelated callers at 4:3 and 16:9.

Appearance projection tests execute the production helper and check both physical shader scales at 4:3 and 16:9. The field shader uses independent c36 axes; the appearance scalar preserves the original ratio-times-scale on both axes before applying the widescreen X factor. The separate Status producer keeps its existing handling.

The original movie/script update returns through its existing epilogue on the movie EOF frame after teardown, allowing the next scene pass to precede dialogue-context advancement. A local compiled probe executes the actual generated function before and after the edit: ordinary and still-playing frames retain their context calls, EOF performs teardown once and defers context calls, and the next frame resumes them. Script wait constants and movie timing are unchanged. The exact reported Legion-to-dialogue boundary has not been recaptured frame by frame with this build.

## Process graphics-memory samples

The selected adapter's DXGI memory API was exercised in the existing ordinary street save, with Japanese, 1×, 4:3 and 30 Hz. D3D11, Vulkan and OpenGL used the same native executable; D3D12 used the subsequent build adding D3D11On12 while retaining the same rendering path; the AMD-integrated D3D11 diagnostic changed only the existing adapter-selection vendor predicate and restored the original source and compiled outputs afterward. The logger samples the selected adapter at startup and at most once per five seconds while frames are presented. Values below are maxima among samples, not continuous peaks or minimum VRAM requirements.

| Selected path | Maximum sampled local usage (MiB) | Maximum sampled nonlocal usage (MiB) |
| --- | ---: | ---: |
| D3D11 / NVIDIA GeForce RTX 5090 | 222.3 | 24.1 |
| Vulkan / NVIDIA GeForce RTX 5090 | 251.9 | 88.9 |
| OpenGL / NVIDIA GeForce GTX 470 | 118.8 | 229.5 |
| D3D12 / NVIDIA GeForce RTX 5090 | 295.0 | 33.6 |
| D3D11_AMD / AMD Radeon(TM) Graphics | 63.4 | 0.0 |

All five samples returned valid local/nonlocal query results and no sampled usage exceeded the corresponding reported process budget. The integrated adapter reports a unified local budget that includes system-memory resources; its zero nonlocal values are a successful API result, not an unsupported-query placeholder. Capacity and segment accounting can differ across drivers and translation layers, so do not add these values to infer a universal physical VRAM requirement or compare only dedicated capacity.

The existing test suite exercises the actual logger with supported queries, unsupported interfaces, unavailable segments, five-second throttling and adapter-reference release. Startup failure/selection checks and native/imported-English builds also pass. The same ordinary street, NPC and interaction capture paths continue to run around 30 FPS. These checks do not establish 512 MiB support, long-session peaks, the exact reported female-player model or the restaurant occlusion case. The [README](../README.md#system-requirements) separates tested reference hardware from requirements that have not been established.

## D3D12 and program updates

D3D12 was exercised through the actual D3D11On12 device path in the same ordinary street save at Japanese 1×, 4:3, 30 Hz. Street, NPC and dialogue counters measured about 29–31 FPS; the captured models had no horizontal gaps. It is not a reproduction of the player's female model or restaurant scene. Startup selection tests cover Auto reaching D3D12 and D3D11 after preceding failures, and exclusive manual D3D12 selection. Production configuration read/write accepts D3D12.

The source program-update command reuses the original lifter, Cargo and CMake dependency graphs. Installer tests check a complete payload before any copy, reject escaping paths, preserve data/configuration/saves, apply changed programs and leave identical files' timestamps alone. The program update deliberately retains installed translated resources; it does not claim to rebuild changed translation data.

The complete local source-check selection passed 32 checks. An actual in-place source update completed without an ISO or Chinese font/movie imports, retaining bytes and timestamps for 14,080 data/configuration/language files and all 96 generated C/header files. Both native and imported-English Ninja builds reported no work after the D3D12 build, demonstrating reuse of the existing compiled outputs.

## Custom keyboard and controller bindings

Production input tests cover default arrow-key D-pad input distinct from numeric-keypad keys, shoulders/buttons/sticks, every trigger byte value, keyboard remapping, controller B-to-A remapping, unbound actions, axis inversion including signed endpoints, invalid/reserved bindings and restoring defaults. Configuration read/write tests exercise both Japanese-only and Chinese-enabled builds, preserve custom/unbound values, and reject invalid writes without replacing the saved profile.

The actual Config dialog/resource is exercised in all three interface languages with controlled host inputs: distinct navigation/keypad and Num Lock/Pause labels, default direction-key selections, held-key rejection, reserved-key rejection, focus-loss cancellation, keyboard/controller capture, Apply, Cancel and Restore defaults. The game was loaded through the existing ordinary-save route at Japanese 1×, 4:3, around 30 FPS. Two attempts to activate the automated game's window were refused by Windows, so live physical-key interaction was not established by those street captures. The production focus restriction was preserved; simulated production-input tests are not a physical-device gameplay claim.

The release update installers also check language-selection mismatches before writing. Original Japanese/Chinese data, settings and saves are excluded from program update payloads. Imported-English hosts are rebuilt from their existing source package; generic binary updates do not replace externally translated executables.
