# Fixed texture coordinate generation

The original game producer sub_002EB6C0 selects Kelvin NORMAL_MAP (0x8511) at 0x002EB741 and REFLECTION_MAP (0x8512) at 0x002EB74E, then emits the same mode for S/T/R at 0x002EB760. Existing Kelvin methods retain component validation and CSV1 mode identities.

Both existing fixed vertex consumers use the already transformed, skinned and optionally normalized normal. NORMAL_MAP exports that normal. REFLECTION_MAP reflects the eye-space position direction about it; infinite viewer uses (0,0,1), local viewer uses normalized eye-space position. Q remains the incoming coordinate; the existing per-stage texture matrix applies afterward. This follows xemu hw/xbox/nv2a/pgraph/glsl/vsh-ff.c, the existing native fixed-function source contract. SPHERE_MAP uses the same reflected vector, exporting only S/T as r.xy/(2*length(r+(0,0,1)))+0.5; incoming R/Q remain unchanged. The existing Kelvin producer restricts sphere generation to S/T. This follows the same primary implementation, without inventing singular-point substitutes. The examined original game producer does not select sphere; support here is established by the legal method contract and actual finite-input fixture, not a claim that gameplay used it.

Kelvin SET_TEXGEN_VIEW_MODEL (0x09CC) accepts only LOCAL_VIEWER=0 and INFINITE_VIEWER=1 and writes the existing CSV0_D TEXGEN_REF bit 20. The bridge carries that bit in the previously unused Fixed.skinning.y component; buffer layout and size are unchanged. Existing skin blending still uses skinning.x. There is one authoritative state bit, with no additional PGRAPH state or renderer.

Fixed mode 0 with generated coordinates or texture matrices enters the existing fixed interpreter even when XYZRHW resembles screen-space input. Program mode 2 keeps its original early dispatch and consumes program texture outputs directly. Unrecognized coordinate modes still stop.

The original GPU fixture verifies 192 combinations per backend/execution configuration: four stages, normal/reflection/sphere, local/infinite viewer, normalization, matrix, and generated two-bone weighting. Independent coordinates include inverse-normal transforms and are compared across all 64 output pixels. A third program pass keeps texgen/matrix enabled and verifies program output is not generated again. D3D11/Vulkan native and software configurations pass. Existing linear/matrix tests remain passing. Invalid 9CC value 2 stops. Restoring the initial prior dispatch produces the original mode-4 stop; restoring the post-normal/reflection dispatch produces the original mode-3 stop in all four configurations; this negative control is retained.

Primary consumption reference: https://github.com/xemu-project/xemu/blob/master/hw/xbox/nv2a/pgraph/glsl/vsh-ff.c
