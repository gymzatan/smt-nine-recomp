# CPU floating environment

Generated x87 instructions, the original CRT save/restore sequence, and guest register checkpoints use the existing shared register state. The additional environment fields retain status, physical-slot tags, opcode, code/data selectors, last instruction/data pointers, MXCSR, and MMX save representation. Integer flags and the original double-backed arithmetic remain the same engine.

The common `vendor/xboxrecomp/src/kernel/recomp_fpu_state.h` encodes legacy 94/108-byte images and the 512-byte extended image. Its `RecompFpuState` is a value view of runtime registers; it is not another interpreter. `recomp_fp_save_extended(void *, const RecompFpuState *)` and `recomp_fp_load_extended(const void *, RecompFpuState *)` are shared with kernel exception CONTEXT handling. Physical x87 indices remain distinct from the logical ST order in saved register areas. Each physical slot retains its raw ten-byte image. MMX writes update only their actual destination slot and retain the other seven images; x87 writes retain the arithmetic result and mark only that slot for derived raw80/MMX synchronization at an observer. Register copies/exchanges preserve the original slot bytes. EMMS marks all tags empty.

The original CRT body at `0x00239B08` saves its x87 environment around a call to `0x002408F0`, then restores its caller state. FNSAVE resets the x87 environment after storing it; FRSTOR restores it without changing SSE registers. FNSTENV masks exceptions after storing the old control word. FLDENV changes the environment while retaining register values. FNINIT and FNCLEX have explicit state operations. Unknown x87 instructions use the existing explicit unsupported-instruction mechanism.

The Xbox CONTEXT floating area starts at offset 4 and contains the extended register image followed by Cr0NpxState; integer registers begin at offset 0x208. The kernel bridge consumes the same extended-image codec for capture/restore and handler-modified contexts. Its saved APC and exception frames retain the full environment and physical raw slot images. No separate floating-image implementation is used. CPU register checkpoints retain the additional environment fields through the original capture/validate/restore APIs.

CPU divide faults retain their native exception-helper call as an ordinary kind-one saved call at the original instruction address. Code, instruction address, frame EBP and returned continuation address are frame locals. Restoration re-enters the helper without repeating division operand reads or earlier instructions. Local retry/skip targets clear the saved call boundary; a function-external continuation retains that boundary until the existing exception transfer takes ownership. A synthetic native exception helper with a waiting generated callback verifies cold and same-process restoration, original parameter retention, once-only callback setup/completion, and the external transfer boundary. The integrated bridge also verifies actual generated DIV through its native dispatch, a waiting handler, handler-modified ECX and a successful retry in cold and same-process restoration. RtlUnwind uses that same context codec and retains handler changes through waiting and nested-collision recovery; its original contract is described in CPU_UNWIND.md.

The existing arithmetic representation is double-backed. Environment serialization does not establish full extended-precision arithmetic, sticky x87 arithmetic exceptions, or guest MXCSR arithmetic semantics. Those require evidence from actual game consumers before further changes. The isolated checks cover the original save/call/restore sequence, binary80 encodings of represented values, empty/zero/valid tags, physical/logical ordering, MMX raw images, SSE state retention, and same-process/cold CPU register restoration. They do not certify whole-game completion.


Floating arithmetic retains its existing double-backed result. A per-physical-slot thread-local validity mask defers derived raw80/MMX updates until a raw store, MMX entry, FPU save, or CPU-register capture observes them. Arithmetic writes always invalidate their destination, including same-value writes; copies and exchanges carry the slot validity with the value. Materialization does not reclassify architectural tags, so explicit environment changes and empty slots remain observable. Exact raw80 loads and untouched slots retain their bytes. Restoring a complete CPU/FPU image clears derived pending work; the mask is internal and does not change serialized state layouts. MMX destination writes still update their raw and double views immediately.

Sources: [Intel instruction manual](https://www.intel.com/content/dam/www/public/us/en/documents/manuals/64-ia-32-architectures-software-developer-vol-2a-manual.pdf), [Xbox CONTEXT definitions](https://github.com/XboxDev/nxdk/blob/master/lib/xboxkrnl/xboxdef.h).

Arithmetic status publication consumes the existing basic-block per-bit demand directly. An instruction updates only demanded bits it defines, retaining other architectural bits for subsequent partial writers. The original block-exit, call, divide-fault, observer, carry-input and conditional-write demand rules remain in effect. Standalone lifter callers retain full status publication by default; conditional shifts and other writer paths retain their existing behavior.
