# RtlUnwind guest contract

Ordinal 312 follows the original 4627 implementation at 80023C41 and its execute-handler trampoline at 8002293C. The supplied TargetIp is unused by that original routine. A missing exception record becomes STATUS_UNWIND. The existing shared context codec supplies the complete accepted integer and floating context, with ReturnValue in EAX and the caller stack after four arguments.

Registrations remain linked while their callbacks run. A temporary original-style collision guard returns ContinueSearch for dispatch and CollidedUnwind with its protected registration for unwind. ContinueSearch unlinks the visited registration; CollidedUnwind unlinks the registration selected through the dispatcher pointer. Invalid dispositions, invalid targets and invalid stack registrations raise the original noncontinuable status through the existing exception path. Exhausting the chain for a target other than the end sentinel takes the existing unhandled second-chance termination directly, without capturing a second context or dispatching callbacks again.

The native unwind frame records its phase, complete CPU state, argument identities, guest scratch/context addresses and active guard in the original continuation system. A callback that waits resumes once at that callback, including nested unwind that already consumed the collision guard. The callback may edit the real context; successful completion restores it through the shared codec. Abandoned native frames remove only a still-linked owned guard.

Private verification covers eleven native modes (including actual nested unwind and both guard dispositions), plus five callback-wait modes in cold and same-process recovery. It does not establish unobserved interrupt-stack unwind behavior or full x86 floating arithmetic certification. Parent integration passes 24 affected kernel and 16 continuation checks, retaining existing exception and create consumers. Generated-corpus integration and complete source build remain separate.
