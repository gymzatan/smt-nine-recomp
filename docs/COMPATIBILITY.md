# Runtime compatibility

The native port retains the game's original command producers, but several hardware and kernel consumers are incomplete. Import routing, accepting a register write and completing a scene do not establish semantic compatibility. The Windows port is approved for an early playable release with these documented limits; complete compatibility, a full playthrough and normal speed in every scene are not certified.

## Connected consumers and actual evidence

Native Vulkan pipelines retain the existing 8192-entry capacity. A miss at capacity uses full-table pipeline retirement: finish and submit current rendering, wait for its serial, then destroy and clear the original pipeline table. Hits keep their existing entries. Pipeline selection precedes the current draw's upload reservation, chunk reference, descriptors and query reset, so retirement cannot leave that draw writing into a submitted command buffer. The original chunk begin and attachment transitions resume drawing. The native fixture crosses capacity using 8193 effective enabled-stencil keys with stable shaders and checks the preserved original query, attachment pixels and subsequent enabled-state draws. Shader destruction retires only entries whose original vertex, geometry or pixel module matches the destroyed module, submitting and waiting once before the first matching pipeline is destroyed; when no pipeline matches, module destruction does not submit or wait for unrelated draws; no second cache or error recovery is introduced.

The original combiner shader-cache key clears general-stage records beyond the active count and clears final inputs/flags only for native draws with the final combiner disabled. Constant colors retain their existing key treatment. The generator, active count and enable fields, non-native final path, other flags, 128-slot LRU and its shader-destruction calls remain unchanged. The focused original GPU fixture compares unused-state HLSL bytes and cache identity/count, active-stage/final shader identities and real pixels; it preserves the non-native final branch. This removes redundant shader compilation identities but does not establish the cause of scene-transition stutter.

The direct Vulkan pipeline cache keys depth write/compare only when depth testing is enabled, stencil parameters only when stencil testing is enabled, blend factors/operation only when blending is enabled, and logic operation only when logical operations are enabled. The key retains original enable bits, shader modules, other state and pipeline creation values. Shader retirement and capacity misses share the original submit/wait release helper; shader retirement selects matching modules while capacity misses release the whole table; the table retains its 8192-entry capacity. These disabled parameters are ignored by Vulkan operations; retaining them as distinct identities caused avoidable pipeline creation and could exhaust the existing 8192-entry limit. The original native fixture covers 8193 disabled-stencil reference/mask combinations and distinguishing enabled-state pixels; execution results belong to its integration receipt. This reduction does not establish the cause or duration of scene-transition stutter.

Guest CPU backedges retain their existing checkpoint, hook, GPU progress and APC services. After those services, the existing ordinary-CPU and DPC waiter counts suppress clock reads and empty lock handoffs when nobody is waiting. Contested execution keeps the original quantum, IRQL and handoff rules; the original decompressor and checkpoint sites are unchanged.

The preserved long-play log ends at Kelvin method `0x0384`, parameter `0xC0800000`: the game's polygon-offset factor is `-4.0`. The original producer at `0x002EB1D0` emits factor, bias and three enable states through `0x002EB640`. Rejecting nonzero values is a compatibility restriction already present in the earliest public source. This exit is not evidence of cumulative memory consumption. No new crash dump or saved state preserves this exact route.

The working source connects factor, bias and mode-specific enables to depth generation. Filled-polygon Z offset uses the screen-space gradient before depth clamp or rejection. Native scaling converts derivatives back to guest pixels. Native polygon POINT/LINE carries the original post-clip polygon depth-plane slope through the existing geometry output to the pixel shader, so wide-line expansion and edge direction do not discard the other gradient component. The raw eight-vector vertex upload stays unchanged; its output depth semantic explicitly carries Z and polygon slope. Standalone points and lines do not inherit polygon-offset enables. Nonconstant-W slope behavior remains incomplete. Nonconstant W slope is explicitly unsupported rather than approximated per pixel. Finite constant-W polygons have exactly zero slope and accept finite nonzero factors in software through the original depth-plane helper, including POINT/LINE before expansion. Native batches use this exact subset when their existing complete CPU/screen outputs prove one positive finite W value throughout the batch. The proof runs once only for an actual W-buffer nonzero-factor offset request; GPU-only program/fixed outputs remain unsupported, with no duplicate transform or readback.

Software depth and stencil comparisons use the original DMA-resolved RAM pixels directly, with the existing depth encoding, stencil operations and row workers. CPU aliases, texture reads and semaphore writes observe the same bytes. No duplicate software depth/stencil image is retained. GPU checkpoints identify RAM authority with `XBGPUR` and pair with the existing physical-memory snapshot; the former cache archive identity is rejected.

All eight stencil operations reach the existing native and software consumers, including fail, depth-fail and pass outcomes, saturation/wrap, write enable, read/write masks and alpha rejection. Original function `0x0017C188` submits increment/decrement-saturate at `0x0017C566` and `0x0017C599`. The existing native operation mapping is reused.

Depth storage retains encoded bits for integer and floating 16/24-bit formats. Raw clears, comparisons and format reinterpretation retain the same cache and checkpoint identities. Native W depth uses Direct3D's provided W; Vulkan compilation already requests the matching position-W convention. Integer depth is quantized before comparison/write. W bias is connected. Constant-W slope is zero for software and proven native complete-output batches; nonconstant W slope and native GPU-only W slope are not certified.

The native depth path shares the existing physical RAM identities and memory-fault ownership with colour, textures and completion outputs. Z16 and Z24S8 images load guest RAM using the submitted zeta pitch or existing Morton layout, publish encoded depth and stencil back before CPU or overlapping GPU consumers, and reload after CPU alias writes. Partial clears retain the other aspect and padding. Same-address width, pitch, format and growing-height reuse publishes the previous image before reinterpreting the same RAM; a smaller clip retains the existing extent. D32 depth uses an exact binary normalization for encoded guest values; clear, RAM transfer and the original pixel consumer share that normalization, preserving equal and ordered comparisons. Read-only depth draws and non-writing stencil states retain clean RAM ownership; repeated writes reuse the existing dirty ownership invariant without querying OS protection again on every draw. Every production protection writer either publishes/retires that owner or preserves NOACCESS across all original CPU views; guest protection requests use the existing host-write boundary. A completed whole-span NOACCESS change also needs no second page-query pass. Checkpoints retain the depth layout, explicit normalization and scaled native image through the original depth cache; incompatible normalization is rejected. These checks cover linear and Morton surfaces on the existing native backends; physical tiled/compressed encodings remain unverified.

Host file reads preserve only dirty colour/depth owners intersecting the destination pages. The existing CPU-write preservation walk is shared by both consumers; short or failed reads retain every untouched byte. A pending output on a destination page completes through the original query FIFO before the host write. Disjoint writes retain unrelated dirty surfaces and pending outputs. Texture guards, aliases and the held write lock keep their existing lifecycle.

Original producer `0x002EB440` can submit enabled color logic operations. All sixteen operations, color masks and blend precedence are connected to the existing software, D3D11/D3D12 and Vulkan output paths. Overlapping draws consume actual destination pixels. The original D3D state cache includes the new operation in its identity; the Vulkan pipeline key includes enable and operation.

The pinned WineD3D dependency implements all sixteen OpenGL logic operations in its existing blend-state path. State identity, capability reporting, blend precedence and clear/blit restoration consume the same operation. The dependency manifest selects the tested build and retains the existing import and event-wakeup preparation. Its corresponding source and build recipe accompany the standalone dependency release.

Kelvin execution consumes the class context already selected by PGRAPH on every subchannel. Nonzero channels use the original texture, constant, vertex and draw consumers. Inline and immediate primitive submission uses the same minimum vertex count as array submission, so a single point and a two-vertex line reach the existing native geometry path. Legacy four-float diffuse writes share generic attribute 3 rather than a separate vertex implementation.

Native screen-output uploads retain the existing eight-vector position, front colors, fog and four texture-coordinate layout. The shared packer selects those fields explicitly from interpreter outputs, so back-color and other software output fields cannot shift native fog/texture inputs or overrun the upload row. Both direct screen triangles/lines and native geometry capture consume this same packing.

Native polygon point, line and fill modes use the original face convention, clipping, culling and provoking color. Ordinary two-sided FILL input with all original vertices inside the W boundary bypasses general edge-clipping bookkeeping and still uses the same visibility, quantization, back-color and output consumers. Clipped and mixed polygon modes retain the general path; vertex positions are quantized once. Per-vertex boundary flags are captured when arrays, indices, inline or immediate vertices are submitted. Whole quads retain their boundary; polygon fans exclude internal diagonals and duplicate point submissions. X/Y clipping creates the required boundary edges and vertices before mode selection. Mixed front/back modes retain original primitive order through the same native draw and upload identities. Points reuse the existing point expansion; aliased line width consumes the original six-integer/three-fractional-bit state and native unit-line rasterizer, including render scaling. No smooth/AA coverage contract is inferred from this path. Polygon POINT bias and Z slope consume the same original polygon depth plane as LINE, before point-square expansion. Active polygon-point parameters select the same original fixed vertex path as standalone points, preserving its eye-distance attenuation and size output.

Polygon stipple consumes all 32 standing pattern rows and the enable state through the existing native pixel shader and software fragment consumers. The asymmetric hardware capture establishes little-endian bytes with most-significant-bit-first X ordering inside each byte, and reversed pattern rows in physical screen Y. Filled polygon fragments are discarded before depth/stencil and color writes; standalone points and lines remain unaffected. Focused actual-output checks cover zero, full, alternating, checkered and asymmetric patterns on software and native paths, including render scaling.

Single-sample smoothing control consumes the original 1D7C enable bit and standing LINE/POLY flags. The original hardware producer and golden images establish that control FFFF0001 suppresses both smoothing modes on AA_CENTER_1 surfaces; these draws use the existing aliased consumers. Flags and effective control survive the original GPU checkpoint. The same registers suffice for accepted 0/FFFF0000/FFFF0001 writes; no duplicate raw state is added. Other sample masks/flags, multisample surface formats and effective analytic smoothing remain explicit unsupported requests. The existing POINTSMOOTH state retains its original point-sprite stage-3 UV meaning.

Software standalone points consume the original fixed/interpreted vertex outputs, including program output register 6 and fixed point parameters. The existing triangle fragment consumer shades the same square expansion as native points, with original odd/even center rounding and stage-3 sprite coordinates. Original primitive identity prevents polygon culling, back colors, stipple and polygon offset from affecting these points. Color, RAM depth and single stencil increments are checked against native output for sizes one through six, both vertex modes and point-parameter enables. Software standalone aliased lines use the same fragment, texture, depth and stencil consumer, with directed diamond-exit coverage, original fixed/program outputs and ordered integer line-width copies. Focused checks compare 90 full native/software coverage images and fixed/program, flat/smooth color plus raw depth/stencil images. Native major-axis interpolation is retained; existing floating-point color packing can differ by one byte at half ties. Original Xbox interpolation precision is not independently certified. Software polygon LINE emits the original clipped boundary edges through the same line/fragment consumer, preserving face mode, culling, flat/back colors and order. Its independent bias enable and Z slope consume the original polygon depth plane before boundary-line expansion. The same depth-plane helper serves software FILL and LINE, including generated clipped boundaries; standalone lines inherit no polygon offset. Software polygon POINT/FILL mode selection uses the same fragment consumer, original face convention and shared submitted boundary identities. Whole quads and polygon fans preserve vertex order; W and X/Y clipping create boundary points before mode selection. POINT-specific offset enable, bias and Z slope are applied from the original polygon plane without inheriting FILL offset or polygon stipple.

Texture address modes wrap, mirrored repeat, edge clamp, border and mirror-once share signed-tap behavior in the software sampler and the original native samplers. Standing per-stage border colors reach D3D11 and Vulkan. Custom Vulkan border colors use the device's custom-border feature and include the color and image format in the existing sampler identity; devices lacking that requested capability report it explicitly. ## Guest kernel objects and dispatch

Imported kernel calls initialize APC timing only when an actual APC wait window begins. New Windows wait aliases use the existing first-free token allocator directly because the newly duplicated native handle has not yet been registered; ordinary callers retain identity lookup through that same allocator. Real alias ownership, release, private-token state and cold restoration remain unchanged.


NtFlushBuffersFile reports an actual host flush failure through its return status and IO_STATUS_BLOCK, with Information cleared. The Windows path retains the host error for the existing diagnostic accessor; the POSIX path uses the existing errno mapping and rejects invalid file descriptors. The focused Windows check exercises successful writable-file flush, a real read-only-handle failure, and an invalid handle. This is per-file flushing; it does not implement whole-device ATA cache flush or standby.

HalRegisterShutdownNotification retains the original guest-owned registration records and signed descending priority, with FIFO order at equal priority and identity-based unregister. HalReturnToFirmware routine 2 removes each record before invoking its stdcall guest callback at the caller's restored IRQL; other routines do not broadcast. Both imported and native entry paths for guest-memory records use the same list and existing guest callback/continuation engine. The list head is in the existing kernel data area and is saved with guest RAM. In-flight imported or native calls nested under a tracked guest root resume their current callback without selecting or invoking it twice. Existing executable identity checks govern machine checkpoints; ordinary game saves retain their original path. Arbitrary host callback registrations are not covered by this connection. The Windows HalReturnToFirmware and HalInitiateShutdown endpoints exit the process; HalReturnToFirmware routine 2 first retains the installed game shutdown notifications. Xbox SMC/power-controller and physical power-off reproduction are outside the Windows port scope. No asynchronous hardware power sequence or SMC audio clamp is claimed.

The bridge writes the Xbox ABI directly: DEVICE_OBJECT is 0x48 bytes before its extension, KINTERRUPT is 112 bytes, KDPC is 28 bytes, KDEVICE_QUEUE is 12 bytes, and event/timer dispatcher sizes are measured in 32-bit words. Guest list links point into guest memory. The original memory-unit device producer at 0x0030F33C requests a 0x170-byte extension and consumes DeviceExtension at offset 0x18. Its entire extension fits the allocation, and embedded storage-device locks use the existing event shadow table.

Interrupt connect/disconnect uses the existing registered ISR table, including duplicate registration and non-owner disconnect behavior. The bus IRQ-to-vector conversion is +0x30, with IRQL 27 minus the bus IRQ. GPU and USB delivery use the registered device IRQL and the existing guest CPU ownership. KeSynchronizeExecution raises to that same level for the original callback and restores its caller's level.

Timer set, expiration and cancellation use the existing scheduler. Relative and absolute deadlines follow the existing virtual clock. Guest Inserted, SignalState, DueTime, Dpc and Period remain connected to the scheduler; cancellation does not reset an already signalled timer. Both initialized objects and title-built events use the same shadow table and native signal objects. Single and multiple waits publish the current native state after consumption, so a second waiter cannot replay an old signal and a new signal is not erased by a returning waiter. Title-built events are seeded from their initial header; the XDK direct-zero reset path is retained under guest CPU ownership. Set/reset/pulse obtain previous state atomically from the native event operation, including the Nt token entry points, and reuse the existing non-consuming checkpoint query for the guest mirror.

The standing DPC stack consumes the original PCR fields and memory ownership. Main and spawned PCRs retain a 0x3000-byte stack without allocation or clearing per callback; the spawned PCR reserves 0x60 bytes before TLS and shares the original owning allocation. FS+0x58 records the active dispatcher stack address, FS+0x5c records its top, and the original exception dispatch/unwind share the same active-stack bounds. The continuation retains interrupted registers, exception chain and IRQL. Physical snapshots use XBPCRS and reject the incompatible former layout before modifying RAM. See technical/DPC_STACK.md. Ordinary game saves are unaffected; old instant states are retained but cannot be loaded across these GPU/PCR layout changes.

The original DPC queue and active-timer table grow with live entries. Distinct DPCs and timers do not disappear at their initial storage capacity. The timer worker, set and cancel paths scan only through the highest occupied timer slot. One-shot expiration and cancellation trim retired trailing slots under the existing lock; checkpoint load derives this bound from the restored table without adding serialized state or reducing capacity. Callback rearming, periodic deadlines and CPU-before-timer lock order remain unchanged. Insertion publishes the original DPC argument fields immediately. Scheduler snapshots retain expanded storage, queue order, callback arguments and timer identities in the existing clock/object recovery path. Allocation failure stops explicitly rather than reporting a successful insertion.

The DPC worker takes guest CPU ownership before claiming a queued callback. Cancellation can still remove it while the worker waits for that ownership. Timer expiration uses the same CPU-before-scheduler lock ordering, signals before invoking the callback and releases the scheduler lock before callbacks can set or cancel timers. Existing checkpoint identities and ownership restoration remain authoritative. Object lifecycle checks also pass through the real import dispatcher. Nonblocking object mutations, IRQL transitions and synchronized callbacks retain guest CPU ownership at that entry; ordinary blocking-call behavior and the existing critical-section contention path are preserved.

Waits retain their native object identities through private aliases in the existing handle table. Closing or reusing the caller's token does not terminate a suspended wait. The owning continuation records the guest token-list allocation; the existing RAM and object serializers restore it, and normal/nonlocal exits release it. Signal-and-wait uses the native atomic operation once and persists its completed signal phase, so cold and same-process restoration cannot release a semaphore or mutant twice.

Timer handles use the existing KTIMER scheduler, shadow identity and native signal object. Notification and synchronization timers retain their reset behavior. Set/cancel/query use the original ETIMER layout and Boolean output widths; query consumes the Xbox two-argument ABI. Expiration carries the current virtual system time into the original DPC/APC path. Active APC timers retain one object reference, belong to the issuing thread's timer list and release that reference on one-shot delivery, replacement, cancellation or thread exit. Type checks prevent the event-backed timer from being accepted by Nt event or signal operations. The original RAM, object and scheduler snapshots retain these identities and remaining deadlines, including when the caller's handle is already closed. Named timer attributes use the same object namespace and lifetime as named events, semaphores, mutants and completion ports.

Named dispatcher objects and directory identities reuse the existing Ke shadow table.
